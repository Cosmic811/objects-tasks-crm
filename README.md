# Объекты и задачи

CRM строительной команды. Постановщик создаёт объекты, назначает задачи и проверяет результат. Исполнитель видит назначенную ему работу и отправляет её на проверку. Каждый переход статуса сохраняется с автором, временем и комментарием.

[Открыть приложение](https://cosmic811.github.io/objects-tasks-crm/)

## Стек и возможности

React 19, TypeScript, Vite 8, Supabase Auth, PostgreSQL и RLS. Нужен Node.js от 22.18.

- Объекты: название, адрес, реальные счётчики задач.
- Задачи: описание, исполнитель, пять статусов, обязательная причина возврата.
- Две роли; чтение защищено RLS, изменения выполняются проверяемыми RPC.
- Мягкое удаление с сохранением истории; объект с незавершёнными задачами удалить нельзя.
- Адаптивные списки, клавиатурная навигация и reduced motion.
- Большие списки отображаются по 50 записей; API загружает все разрешённые страницы без молчаливого обрезания.

## Локальный запуск

```bash
npm ci
# Скопируйте .env.example в .env.local и заполните URL и публичный ключ.
npm run dev
```

Переменные: `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`. Допустим publishable/anon key, но не service_role. Без конфигурации приложение показывает инструкцию подключения.

## Настройка Supabase

1. Создайте отдельный проект Supabase.
2. Примените два SQL-файла из [supabase/migrations](supabase/migrations) в порядке имени через SQL Editor или Supabase CLI. Не применяйте одни миграции двумя способами.
3. Отключите открытую регистрацию в Authentication. Создайте подтверждённые аккаунты сотрудников и профили с ролями manager/executor. Не храните роли в изменяемых пользователем metadata.
4. Для отдельной демонстрационной базы можно использовать [seed.sql](supabase/seed.sql). Он ожидает аккаунты manager@crm.example, executor1@crm.example, executor2@crm.example и создаёт три объекта и пять задач. Повторное заполнение блокируется. Не запускайте seed на рабочей базе.
5. В Data API публикуйте только схему public. Схема private не должна входить в exposed schemas.

Пароли задаёт администратор и передаёт приватно. Публичный frontend не содержит секретных ключей.

## Проверки

```bash
npm run lint
npm run typecheck
npm test
npm run build
node scripts/check-public.mjs
npm audit --omit=dev
```

`npm test`: 76 проверок PostgreSQL (роли, RLS, RPC, переходы, конфликты, аудит, удаление) и 9 проверок транспорта (пагинация, ошибки, отмена, таймаут полного ответа и отсутствие автоматического повтора через SDK).

Для отдельного тестового проекта скопируйте `.env.test.example` в `.env.test.local`, укажите доступы трёх тестовых аккаунтов и запустите `npm run test:api`. Сценарий создаёт и скрывает только свои проверочные записи, сохраняя аудит. Не используйте производственную базу. Локальный отчёт по умолчанию: `.cache/qa/supabase-api.json`; путь можно изменить через `TEST_REPORT_PATH`. Эти файлы не публикуются.

Ошибка загрузки показывается с повторным запросом и не заменяется пустым списком. При неопределённом результате сохранения приложение предлагает проверить данные перед повтором. Каждый сетевой JSON-запрос ограничен 20 секундами, включая чтение ответа; автоматические повторы PostgREST отключены.

## Публикация

Статический хостинг, сборка `npm run build`, каталог `dist`. Для подпапки задайте `VITE_BASE_PATH=/objects-tasks-crm/`. HashRouter позволяет открывать карточки напрямую и обновлять страницу без серверных rewrite-правил.

В GitHub задайте repository variables `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY`; Settings → Pages → GitHub Actions. Workflow проверяет Pull Request без публикации. После слияния в main выполняет проверки, сборку и деплой Pages. Service role не требуется.

Шрифт Manrope поставляется локально, [лицензия OFL](docs/licenses/Manrope-OFL.txt). Иконки Lucide. Палитра, размеры, радиусы и motion заданы в `src/styles/`; центральные токены находятся в `tokens.css`.
