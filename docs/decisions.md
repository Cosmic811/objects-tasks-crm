# Решения и допущения

- React, TypeScript и Vite. Supabase отвечает за вход, хранение данных и серверные ограничения. Дополнительный backend не нужен.
- Две роли хранятся в profiles, а не в изменяемых пользователем metadata. Профили создаются администратором. Пользователь не может менять собственную роль через API.
- Чтение таблиц защищено RLS. Прямые INSERT, UPDATE и DELETE для клиентских ролей отозваны. Для изменений есть пять RPC с проверкой текущего пользователя. Это закрывает и произвольную смену статуса через PATCH.
- SECURITY DEFINER используется только для проверяемых функций. У них пустой search_path, явные схемы и ограниченный EXECUTE. Вспомогательные функции находятся в private, который не нужно публиковать в Data API.
- Переход блокирует объект, затем задачу. Проверка, обновление статуса и запись истории проходят одной транзакцией. Переданная версия updated_at защищает от устаревших действий и двойного нажатия из разных вкладок.
- Для устаревшей версии возвращается прикладной конфликт PT409 (HTTP 409), а не SQLSTATE 40001, предназначенный для сбоев сериализации. Это отдельно проверено двумя конкурентными HTTP-запросами: один успешный переход, один отказ и одна новая запись истории.
- При создании задачи в историю добавляется отдельная запись с исходным статусом null и новым статусом «Новая».
- Для объектов и задач применяется мягкое удаление. Объект с активными задачами удалить нельзя. Если остались только принятые задачи, объект и эти задачи скрываются вместе. История физически сохраняется. Просмотр архива через пользовательский интерфейс не входит в ТЗ.
- Перенос задачи между объектами не поддерживается. Название, описание и исполнитель редактируются постановщиком без сброса статуса; исходный автор сохраняется. Журнал фиксирует статусы, а не каждую правку текста или назначения.
- Связанные профили защищены внешними ключами. Удаление Auth-пользователя с профилем запрещено, чтобы сохранить авторство. Для отключения доступа следует блокировать аккаунт в Supabase Auth.
- Исполнитель видит своё имя, автора и участников истории доступных ему задач. Полный список сотрудников доступен постановщикам. Email не хранится в публичных профилях.
- В приложении нет открытой регистрации, чата, Kanban, уведомлений или аналитики. Обновление списков происходит при открытии страницы и после операции. Для просмотра изменений другого пользователя можно обновить страницу.
- HashRouter позволяет открывать карточки по прямой ссылке на статическом хостинге без серверной переадресации.
- Проверки PostgreSQL выполняются через PGlite. В них имитируются только Auth users и auth.uid(), сами политики и функции выполняет PostgreSQL. Они не заменяют проверку Supabase Auth и Data API, для которой подготовлен отдельный сценарий.
- Дополнительные расходы не требуются. Активные пароли не публикуются в репозитории. Публичный ключ Supabase допустим в браузере, service_role не используется приложением.
